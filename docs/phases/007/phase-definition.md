# Phase 007 — Concept Mapping, Interaction Semantics & User-Visible Representation

## Role in the lifecycle

Phase 007 connects the conceptual model to the experience through which users perceive, invoke, distinguish, and understand concept behavior. It remains design work: it defines experience semantics without implementing an interface.

## Methodological intention

Ensure that concept state, actions, distinctions, and composed behavior can be represented to users in ways that preserve the intended mental model and observable semantics.

## Primary design questions

- How can users perceive the state that matters for each concept?
- How can users invoke or participate in concept actions?
- What names, labels, distinctions, or representations communicate the concept accurately?
- What feedback is required to make action effects intelligible?
- How do synchronized concepts appear together without obscuring their independent meanings?
- What information or conditions must be visible before consequential actions?
- Does any proposed mapping create a misleading mental model or hide relevant state, authority, or consequence?

## Prerequisites

Phase 006 must provide a sufficiently stable concept, synchronization, and application-scope model to know what must be mapped for relevant product variants.

## Expected durable outputs

Typically includes concept-to-experience mappings, user-visible state/action semantics, linguistic decisions, interaction/feedback obligations, disclosure/visibility requirements, variant differences where relevant, and unresolved familiarity/usability concerns for Phase 008.

## Explicit exclusions

This phase must not select frontend frameworks, component libraries, route structures, view-model classes, CSS systems, native/web technology, transport mechanisms, or executable UI architecture.

## Entry criteria

The relevant concept set, synchronizations, and application scope are explicit enough that user-visible mappings can be evaluated against known semantics rather than invented in isolation.

## Exit criteria

The phase may exit when important concept state and actions are meaningfully perceivable and invocable; terminology and interaction semantics preserve the intended conceptual model; cross-concept mappings are coherent; and no representation silently changes underlying concept meaning.

## Control structure

The phase begins with a mandatory `007-A` start gate, which derives project-specific mapping and interaction-semantics subphases. The final subphase is consolidation, exit review, and handoff.
